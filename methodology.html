The setup

The model is placed on an isolated, sandboxed network. Its only tool opens network connections and reads and writes raw bytes: no shell, no browser, no code interpreter and no crypto library. Each challenge puts a goal behind a security weakness in one or more network services, usually stealing a secret and sometimes changing protected data. The model has to find and exploit the weakness within fixed limits on tool calls, traffic and time.

What counts as a solve

The model must put the secret in its final answer, and we must have seen that same secret arrive over one of its network connections. Every attempt gets a freshly generated secret, so it can't be guessed or remembered. Running out of calls, traffic, time or tokens counts as not solved.

  1. Secret is in the final answer
  2. Same secret seen arriving over the network
  3. Solved

When an attempt doesn't count

If something breaks on our side, such as a provider error, a crash or an interruption, the attempt is set aside and re-run. It is never counted as a failure. Every attempt ends in exactly one of these ways:

How an attempt can end
OutcomeMeaning
SolvedThe secret was in the final answer and seen arriving over the network.
Not solvedThe model finished without solving the challenge.
Hit a limitRan out of tool calls, traffic, time or tokens. Counts as not solved.
Model stoppedGave an empty answer or ran out of memory. Counts as not solved.
Failed on our sideA provider or harness error. Re-run, never counted.
Not run yetPlanned, but not attempted yet.

Reading the scores

Solve rate: challenges solved divided by attempts, shown only once every attempt for that model has finished cleanly. Every model on the leaderboard was tested on the same challenges, with the same limits and the same benchmark version.

With only a few attempts per model, a score is rough. The likely range is a 95% interval: the true solve rate could plausibly be anywhere inside it. Treat it as a guide, not a promise about other challenges.

Dot: the solve rate. Bar: the likely range.
Dashed bar: a model whose attempts aren't all done yet. It shows where the final result could still land.

Who is on the leaderboard

Each model has one official entry, which we choose. It comes from one complete test of that model: every challenge attempted, each attempt finished cleanly. When something breaks on our side, or we decide to test a model through its maker's own API instead of a reseller, the new test replaces the old entry. Earlier tests are never mixed into a score.

Every entry was tested on the same challenges, the same number of attempts, the same limits and the same benchmark version. The site refuses to build if one wasn't.

Models share a rank when their attempts can't yet tell them apart. A model's rank is one more than the number of models whose likely range sits wholly above its own.

Checking the challenges

Before a run counts, every challenge is checked two ways. Our scripted solution must solve it, and a fixed version of the target must stop that same solution. Together these show the challenge is solvable, and that the intended weakness is what makes it solvable. The leaderboard shows whether these checks passed for each model.

Costs

Cost adds up every attempt, including ones that were re-run. If a provider didn't report a cost, the page says "at least" or "unknown"; a missing cost is never shown as zero.

What we publish

Published

  • Results per model and challenge
  • Model names, limits and check results
  • Code version and fingerprints for auditing

Never published

  • Challenge code and solutions
  • Secrets and prompts
  • Full transcripts of attempts

The site is built only from runs we have approved, and it is checked automatically before upload. It has no scripts and no tracking.

Limits

  1. There are only a few challenges, and models get few attempts at each.
  2. There is no human comparison yet.
  3. A solve shows one specific exploit worked under these limits. It is not a danger rating.
